# Sample decks produced by `mode: powerpoint`

These artifacts demonstrate the plugin's `mode: powerpoint` output end-to-end. They are generated by [`scripts/build-deck.js`](../../scripts/build-deck.js), which uses [PptxGenJS](https://gitbrent.github.io/PptxGenJS/) — the from-scratch path Anthropic's `pptx` skill recommends in its `pptxgenjs.md` reference.

## diagramming-hero-diagrams.pptx

Five slides showing the four hero diagrams that ship in this PR:

1. (auto) Title card — deck name + author
2. Aaron's expanded Katalyst thesis (v2, hand-authored canonical reference)
3. RIC-401 — the 3-loop design process (plugin-rendered)
4. Katalyst taxonomy — artifact dependencies (plugin-rendered)
5. Why Katalyst exists — plugin-rendered v1 (simpler take on the same argument)

Each slide has speaker notes covering the framing, who the audience is, and the key takeaway. 16:9 widescreen, blue title bar with white bold title + subtitle, image scaled to body region with margins, attribution footer + slide number.

The accompanying `diagramming-hero-diagrams-title-thumb.png` is a Quick Look–generated thumbnail of slide 1, useful as a preview without needing to open PowerPoint.

## How to regenerate

```bash
cd plugins/diagramming
npm install                                   # one-time, installs pptxgenjs

SPEC=docs/decks/diagramming-hero-diagrams.spec.json
OUT=docs/decks/diagramming-hero-diagrams.pptx
node scripts/build-deck.js "$SPEC" "$OUT"
```

## Spec shape

```jsonc
{
  "title":  "Deck title (used in title card + footer + filename)",
  "author": "Optional attribution",
  "slides": [
    {
      "title":    "Slide title (becomes the blue bar at top)",
      "subtitle": "Optional subtitle inside the bar",
      "image":    "/absolute/path/to/diagram.png",
      "notes":    "Speaker notes (any length)."
    }
  ]
}
```

The plugin's two skills (`architecture-diagrams`, `flow-diagrams`) emit this shape automatically when invoked with `mode: "powerpoint"`. You can also author it directly for a custom deck (as was done here).

## Visual verification protocol

`build-deck.js` is deterministic — same spec, same output. The verification we use:

1. **Structural**: confirm via PptxGenJS's API or `unzip -l` that the .pptx contains the expected slide count + image references.
2. **Visual**: thumbnail via `qlmanage -t -s 1920 -o <dir> <file.pptx>` (macOS native, slide 1 only) OR `soffice --headless --convert-to pdf` (cross-platform, all slides; needs LibreOffice with quarantine cleared on first run).
3. **Native**: open in Keynote / PowerPoint and step through slides.

PR #5 used Keynote-step-through visual verification before committing.
